---
title: "Metrics"
description: "Prometheus-compatible metrics endpoint for node-level observability."
---

The Metrics endpoint exposes Prometheus-compatible metrics for each TrueParser node. Use this endpoint to integrate node telemetry into your existing monitoring stack, for example Grafana, Datadog, or Prometheus.

---

## Endpoint

```http
GET https://{region-code}.trueparser.net/metrics
```

---

## Authentication

None required. This endpoint is publicly accessible to support scraping by external monitoring systems.

<Warning>
  While unauthenticated, this endpoint is rate limited to prevent abuse. Metrics are node-level - they reflect the state of the specific node you query, not your application's global state. For application-level usage, use the [Usage](/api-reference/usage) endpoint instead.
</Warning>

---

## Response

Returns metrics in the standard [Prometheus text exposition format](https://prometheus.io/docs/instrumenting/exposition_formats/):

```text
# HELP TrueParser_connections_total Total active WebSocket connections
# TYPE TrueParser_connections_total gauge
TrueParser_connections_total 247

# HELP TrueParser_documents_active Number of active document sessions
# TYPE TrueParser_documents_active gauge
TrueParser_documents_active 42

# HELP nodejs_heap_size_used_bytes Process heap size used in bytes
# TYPE nodejs_heap_size_used_bytes gauge
nodejs_heap_size_used_bytes 85345280
```

The exact metrics available depend on the `prom-client` configuration and may include both TrueParser-specific and Node.js runtime metrics.

---

## Rate limiting

This endpoint uses the `HEALTH` rate limit policy. A typical Prometheus scrape interval of 15-30 seconds is well within limits.
