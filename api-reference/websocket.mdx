---
title: "WebSocket Sync"
description: "The core of TrueParser for real-time Yjs document synchronization."
---

The WebSocket endpoint is the core of TrueParser. All Yjs document updates, awareness state, and heartbeats flow through this high-performance connection.

<Important>
  Always call the [Discovery API](/api-reference/discovery) first to resolve the current active region for a document. Connecting to the wrong region will result in a 4009 redirect.
</Important>

---

## Endpoint

```http
wss://{region}.trueparser.net/{documentName}
```

Example: `wss://eu-central-1.trueparser.net/my-document-id`

---

## Authentication

TrueParser supports three ways to authenticate the WebSocket handshake. Method 1 is recommended because it keeps the token out of browser history and server logs.

| Method | Implementation |
| --- | --- |
| WebSocket Sub-protocol | `protocols: ['access_token', 'YOUR_JWT']` |
| Query Parameter | `wss://{region}.trueparser.net?token=YOUR_JWT` |
| Authorization Header | `Headers: { 'Authorization': 'Bearer YOUR_JWT' }` |

---

## Connection example

Using the standard `y-websocket` provider:

```js
import * as Y from "yjs";
import { WebsocketProvider } from "y-websocket";

const ydoc = new Y.Doc();

// 1. Resolve URL via Discovery API first
// 2. Initialize provider
const provider = new WebsocketProvider(
  "wss://eu-central-1.trueparser.net",
  "my-document-id",
  ydoc,
  {
    // Pass JWT via sub-protocol
    protocols: ["access_token", "YOUR_JWT"],
  },
);
```

## Close codes

If a connection is rejected or closed, TrueParser returns one of the following codes:

| Code | Name | Description |
| --- | --- | --- |
| 4001 | Missing Token | No JWT was provided in the handshake. |
| 4002 | Invalid Token | Token is expired, malformed, or has an invalid signature. |
| 4003 | Forbidden | The token is valid but the tenantId or appId claims are rejected. |
| 4004 | Connection Limit | Your application has reached its concurrent connection cap. |
| 4005 | Document Limit | Your application has reached its concurrent document cap. |
| 4006 | Rate Limit | Request frequency from this IP is too high. |
| 4007 | Invalid Name | The document name violates internal naming rules. |
| 4008 | User Limit | The max number of users per document is reached. |
| 4009 | Wrong Region | The document is active in another region. The reason field will contain `REDIRECT:wss://...`. |

---

## Handling redirection

If you receive a `4009` close code, your client should parse the reason string to find the correct regional URL and reconnect immediately:

```js
provider.ws.onclose = (event) => {
  if (event.code === 4009 && event.reason.startsWith("REDIRECT:")) {
    const newUrl = event.reason.replace("REDIRECT:", "");
    console.log("Redirecting to:", newUrl);
  }
};
```
