---
title: "Authentication"
description: "How TrueParser handles identity for both management and parsing operations."
---

TrueParser implements a strict separation between **Management Access** (human users in the dashboard), **Identity Authority** (API authentication), and **Parsing Operations** (document processing).

---

## 1. Management Access (Dashboard)

The **TrueParser Dashboard** is the administrative UI where your organization manages its ecosystem.

- **URL**: `https://dashboard.trueparser.com`
- **Identity**: Dashboard access is restricted to **Tenant Users**.
- **Credentials**: Email and password.
- **Purpose**: Manage tenants, create applications, assign plans, and view billing.

---

## 2. Machine Access (API Auth)

To access the parsing engines, your backend services must obtain a security token from the **Identity Authority**.

- **Auth Endpoint**: `https://admin-api.trueparser.com/connect/token`
- **Identity**: API access is granted to **Tenant Applications**.
- **Credentials**: `client_id` and `client_secret`.
- **Flow**: OAuth 2.0 Machine-to-Machine (Client Credentials).

### Obtaining a Token

Exchange your application credentials for a security token:

```bash
curl -X POST https://admin-api.trueparser.com/connect/token \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "grant_type=client_credentials" \
  -d "client_id=YOUR_CLIENT_ID" \
  -d "client_secret=YOUR_CLIENT_SECRET" \
  -d "scope=TrueParser.API offline_access"
```

### Token Lifetimes and Rotation

| Token Type | Lifetime | Behavior |
| :--- | :--- | :--- |
| **Access Token** | 15 Minutes | Used as a Bearer token in the `Authorization` header for parsing. |
| **Refresh Token** | 14 Days | Used to obtain a new access token without re-sending the secret. |

<Important>
  **Refresh Token Rotation.** TrueParser uses **sliding rotation**. Every time you use a refresh token to obtain a new access token, the system issues a **new refresh token** and invalidates the previous one. This provides a continuous session while ensuring high security.
</Important>

---

## 3. Parsing Operations (The Engine)

The **TrueParser API** handles document ingestion and parsing orchestration using the credentials issued by the Identity Authority.

- **Parsing API**: `https://api.trueparser.com`
- **Authorization**: Bearer JWT issued by `admin-api.trueparser.com`.

---

## Security Token Claims

Your access token is a signed JWT containing your usage quotas (captured as Document Units).

```json
{
  "iss": "https://admin-api.trueparser.com",
  "sub": "your_client_id",
  "aud": "TrueParser.API",
  "tenantid": "3f9a6c6e-...",
  "appId": "7b1c0d8c-...",
  "licenseRegionCode": "aws-us-east-1",
  "allowedEngines": ["PDF", "GIS", "CAD", "SQL"],
  "limits": {
    "maxUnitsPerMonth": 5000,
    "maxDocumentSizeMb": 100,
    "requestsPerMinute": 60
  }
}
```

<Tip>
  **Enabling Quotas.** Your application credentials will always issue a token. To include parsing limits in your `limits` claim, ensure a plan is selected for the application in the dashboard.
</Tip>

---

## Token Renewal

Renew your session using the `refresh_token` flow:

```bash
curl -X POST https://admin-api.trueparser.com/connect/token \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "grant_type=refresh_token" \
  -d "refresh_token=YOUR_REFRESH_TOKEN" \
  -d "client_id=YOUR_CLIENT_ID"
```
