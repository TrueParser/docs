TrueParser operates a geographically distributed infrastructure to ensure high availability, low processing latency, and strict compliance with local data residency regulations. 

A **License Region** represents the physical and logical boundary where an organization’s license profiles, usage metrics, and parsing transactional metadata are stored.

---

## The License Regions Screen

You can view all available regions supported by the platform under the **License Regions** section in your dashboard.

![License Regions Screen](/images/license-region/license-regions.png)

This screen serves as a central registry to review active regions and identify their official **Region Codes**. In the details view, you will find:

*   **License Region Name**: The customer-friendly geographic boundary (e.g., `United States`, `Europe`).
*   **Region Code**: The precise identifier (e.g., `us-east-1`, `eu-central-1`) required when configuring external integrations.

---

## Deciding Your Storage & Residency Requirements

When creating machine client applications, you must match them with a specific License Region. 

<Tip>
    **Data Custody Selection**: Always select your License Region based on your specific business location, end-user latency requirements, and regional regulatory compliance constraints (such as GDPR in Europe).
</Tip>

### How Regions Bind to Applications

During the **Application Creation** flow, you are prompted to select an active License Region (as covered in the [App Setup Guide](/dashboard/app-setup)):

1.  **Creation Selection**: You select a predefined region from the dropdown menu (e.g., `Europe`).
2.  **Infrastructure Routing**: The control plane validates the region selection and automatically maps the application to a dedicated, high-performance regional database cluster located within that region.
3.  **Data Isolation**: All subsequent documents parsed, access logs generated, and usage quotas consumed by that application are held strictly inside that region's database shard.
4.  **Token Issuance**: When your backend requests an access token using the app's Client ID and Secret, the resulting JWT carries secure claims identifying the assigned `LicenseRegion` and database router code, allowing the Parsing API to validate permissions locally.

---

## Architectural Invariants

*   **Selection is Permanent**: To guarantee transaction history integrity and prevent database routing mismatches, the License Region is set permanently at creation time and **cannot be modified later** on an active application.
*   **Migrating Regions**: If your organization's storage requirements change or you need to switch database regions, the recommended flow is to create a new application pointing to the target region, configure its S3 bucket, and migrate your API traffic to the new credentials.
