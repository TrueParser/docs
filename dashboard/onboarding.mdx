This page describes the current developer onboarding flow for the control plane.

If your goal is to get from signup to a working backend integration, this is the path to follow.

## 1. Create Your Tenant Account

Create your tenant account at [dashboard.trueparser.com](https://dashboard.trueparser.com).

- new tenant registrations start in `Pending Activation`
- a welcome email is queued after registration
- the host currently has Google authentication configured for dashboard sign-in

At this point, you have a tenant record, but it is not ready for machine access yet.

## 2. Wait For Activation

New tenants are activated in a separate step.

- when the tenant becomes active, an activation email is sent
- that email includes the configured platform URL

Until the tenant is active, tenant apps under that tenant cannot complete normal token issuance.

## 3. Create Your First App

Your app is the machine identity your backend or Demo UI will use to request tokens.

<Steps>
  <Step title="Create The App">
    Open **Apps** in the dashboard and create a new tenant application.
  </Step>
  <Step title="Choose A Region">
    Select a valid license region. The backend resolves the region and stamps the app with the region and database metadata it needs later.
  </Step>
  <Step title="Add Allowed Domains">
    Optionally add up to three allowed domains such as `localhost:3000` or `api.example.com`.
  </Step>
  <Step title="Save Credentials">
    Capture the generated `client_id` and plaintext `client_secret` returned at creation time.
  </Step>
</Steps>

<Warning>
  The plaintext `client_secret` is shown only once when the app is created. If you lose it, regenerate the secret from the dashboard. The regenerated secret is also shown only once, and the old secret is invalidated.
</Warning>

## 4. Optional: Set Up Storage Or Demo Testing

If your tenant uses its own S3-compatible storage, configure it on the app before going live.

- storage is configured per app
- the platform uses your stored storage credentials on your behalf
- your app still retrieves results through the API

If you are testing manually, connect the Demo UI to this app and upload sample documents there.

## 5. Understand The Required App State

For a tenant app to issue tokens successfully:

1. the app must be enabled
2. the tenant must be active
3. the app must have a license region
4. the app must have a stamped database code

## 6. Assign A Plan If You Need Quotas

Plans are optional for token issuance, but they matter if your backend depends on the `entitlements` claim.

- no plan assigned: token can still be issued, but no `entitlements` claim is added
- usable plan assigned: token includes `entitlements` in Document Units and feature flags
- retired plan assigned: token issuance is blocked

Free plans can be assigned directly, but only one app per tenant can use a free plan.

## 7. Use The App Credentials From Your Backend

Once the tenant is active and the app is created, your backend can request a token using `client_credentials`.
